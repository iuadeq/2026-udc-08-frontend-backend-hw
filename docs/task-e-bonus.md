# Task E (bonus) — Шлях 3: набір тестів на авторизацію

## Що зробили

Пройшлися кожним ендпоінтом «не тим користувачем» — Оля (id=1) намагається
дістатися до нотатки Тараса (id=3), а Тарас — до нотаток Олі. Кожен тест
перевіряє, що сервер відмовляє з 404 (а не видає чужі дані).

| Ендпоінт | Як чужий користувач | Очікувано | Фактично |
|---|---|---|---|
| `GET /api/notes` | Оля запитує список — бачить лише свої 2 нотатки, не бачить нотатку Тараса | 200, масив з 2 нотаток Олі | 200, `[{title:"Список покупок"}, {title:"Ідеї для відпустки"}]` — коректно |
| `GET /api/notes/:id` | Оля запитує `GET /api/notes/3` (нотатка Тараса) | 404 | **До фіксу: 200 з повним вмістом нотатки Тараса (включно з `user_id` та текстом "пароль від сейфа: 1234")**. Після фіксу: 404 — коректно |
| `POST /api/notes` | Тарас створює нотатку — вона прив'язується до його id | 201, нотатка з user_id=2 | 201 — нотатка створена для Тараса, не з'являється у Олі. Коректно |
| `DELETE /api/notes/:id` | Оля намагається видалити `DELETE /api/notes/3` (нотатка Тараса) | 404 | 404 — коректно, нотатка Тараса залишається на місці |
| `PATCH /api/notes/:id/archive` | Оля намагається архівувати `PATCH /api/notes/3/archive` (нотатка Тараса) | 404 | 404 — коректно, стан нотатки Тараса не змінився |

## Що знайшли

Єдиний пропуск авторизації був у засіяному ендпоінті `GET /api/notes/:id`:

- SQL-запит використовував `WHERE id = ?` без перевірки `user_id`
- Будь-який автентифікований користувач міг прочитати будь-яку нотатку за id
- Це критична вразливість: нотатка Тараса містить текст "пароль від сейфа: 1234"
- Витік даних відбувався непомітно — 9 засіяних тестів не ловили цю проблему, бо
  жоден з них не робив крос-юзерний запит на читання

Інших пропусків не виявлено — всі решта ендпоінтів (список, створення, видалення,
архівування) правильно обмежують доступ по `user_id`.
